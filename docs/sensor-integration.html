Integration — Sensor Detail APIs

Tài liệu tích hợp cho FE web (role owner + manager) và app mobile (role farmer). Luồng: danh sách milestone → danh sách thiết bị (assignment) → danh sách sensor → biểu đồ & thống kê 1 sensor.

Endpoint đã có sẵn Endpoint mới owner · manager · farmer
Mô hình truy cập: sensor luôn truy cập trong ngữ cảnh 1 assignment (kit gắn vào milestone). Sensor lấy ra từ active binding (ProductionMilestoneIotDeviceSensorBinding). Mọi role phải lấy milestoneId → assignmentId trước khi gọi API sensor.
3 role dùng chung bộ API. Bước 3–4 (sensor) giống hệt nhau cho owner/manager/farmer — chỉ bước 1–2 (điều hướng) khác route theo role. API 2 & API 3 là route chung, không có prefix role.

Khác biệt: chỉ ở bước 1–2 (điều hướng tới assignmentId) — owner/manager đi qua crop-season, farmer đi qua current-upcoming-milestones. Bước 3 (API 1) chỉ khác prefix role trong route; bước 4 (API 2+3) là route chung y hệt cho cả 3 role.

2. Xác thực & response wrapper

  • Mọi request: header Authorization: Bearer <accessToken>.
  • Role: owner manager farmer. Role khác → 403.
  • owner: sở hữu farm + subscription active. manager / farmer: thành viên active của farm.
  • Response bọc wrapper chuẩn — đọc trường data: 
    { "statusCode": 200, "message": "Success", "data": { ... } }

3. Bước 1–2 — Điều hướng tới assignment

Bước 1 — Danh sách milestone

GET /production-milestone/{owner|manager}/crop-season owner manager

Danh sách milestone (phân trang) thuộc crop-season caller quản lý — owner: mọi farm sở hữu; manager: zone được giao. Lấy 1 mùa vụ: /crop-season/:cropSeasonId.

data: {
  "data": [
    { "id": "milestone-uuid", "cropSeasonId": "uuid", "stageName": "Ra hoa",
      "milestoneOrder": 3, "status": "in_progress", "startDate": "ISO", "endDate": "ISO" }
  ],
  "meta": { "page": 1, "limit": 10, "totalItems": 12, "totalPages": 2 }
}
GET /production-milestone/farmer/current-upcoming-milestones farmer

Milestone hiện tại (in_progress) + sắp tới (pending) của farmer, mọi zone. Không có query param.

data: {
  "data": [
    { "id": "milestone-uuid", "stageName": "Ra hoa", "milestoneOrder": 3,
      "status": "in_progress", "cropSeasonId": "uuid",
      "zoneId": "uuid", "zoneName": "Khu A", "farmId": "uuid", "farmName": "Trang trại Hoa Sen" }
  ]
}

Group theo zoneName trên UI nếu farmer trải nhiều zone.

Bước 2 — Danh sách assignment của milestone

GET /production-milestone-iot-device/{owner|manager}/milestone/:milestoneId/assignments owner manager

IoT assignment (kit gắn vào milestone) + sensor đã bound. Bản phân trang + filter: .../assignments/search?q=&status=&page=&limit=.

data: [
  {
    "assignmentId": "5a8d3f02-...",   // ← chìa khoá cho API 1/2/3
    "iotDeviceId": "uuid", "milestoneId": "uuid", "zoneId": "uuid", "farmId": "uuid",
    "device": { "id": "uuid", "label": "K013", "status": "active" },
    "sensors": [ { "sensorId": "uuid", "sensorType": "soil_moisture" } ]
  }
]
GET /production-milestone/farmer/milestones/:milestoneId/assignments farmer

Danh sách thiết bị gắn vào milestone — phân trang + filter q (tên thiết bị) / status (available|purchase|install|active|error|revoked), page, limit.

data: {
  "data": [
    {
      "assignmentId": "5a8d3f02-...",   // ← chìa khoá cho API 1/2/3
      "startAt": "ISO" | null, "endAt": "ISO" | null, "assignedAt": "ISO",
      "device": { "iotDeviceId", "deviceName", "deviceType", "macAddress", "status" },
      "sensors": [ { "sensorId", "sensorType", "status", "minValue", "maxValue" } ]
    }
  ],
  "meta": { "page", "limit", "totalItems", "totalPages", "hasNextPage", "hasPreviousPage" }
}

Milestone đã completed / không có quyền → 404.

4. API 1 — Danh sách sensor của assignment

GET /sensor-reading/{owner|manager|farmer}/assignment/:assignmentId/latest Bước 3

Mô tả

Toàn bộ sensor đang active-bound vào assignment, kèm reading mới nhất, ngưỡng an toàn, cờ isSafe và device{id,label}. Đã đủ metadata — không cần API "chi tiết sensor" riêng. Prefix route theo role của caller.

Response data

{
  "assignmentId": "5a8d3f02-...",
  "zoneId": "383d5d20-...",
  "milestoneId": "21339545-...",
  "data": [
    {
      "sensorId": "4ec6f20b-...",
      "sensorType": "soil_moisture",
      "device": { "id": "adcbc2e7-...", "label": "K013" },  // label = mã kit; null nếu chưa gán
      "timestamp": "2026-05-21T06:30:00.000Z",              // null nếu chưa có reading
      "value": 42.5,                                        // null nếu chưa có reading
      "minValue": "0", "maxValue": "100",                   // dải vật lý — trục Y (decimal string)
      "threshold": { "source": "milestone", "optimalMin": 20, "optimalMax": 60 },  // null nếu chưa gắn
      "isSafe": true,                                       // null nếu thiếu threshold/reading
      "sensorStatus": "active"                              // active|inactive|calibration|error|damaged
    }
  ]
}

Gợi ý render trạng thái

Hiển thịĐiều kiện
Bình thườngsensorStatus = active & isSafe === true
Cảnh báoisSafe === false (reading vượt ngưỡng an toàn)
LỗisensorStatus ∈ {error, damaged} hoặc value === null

Hiển thị tên kit bằng device.label (vd "K013"), không hiện device.id.

5. API 2 — Time-series theo interval

GET /sensor-reading/assignment/:assignmentId/sensor/:sensorId/series-interval?interval=1h Bước 4

Mô tả

Dữ liệu chart, gom nhóm (bucket) theo interval — mỗi điểm là trung bình reading trong bucket. Cửa sổ tính từ reading đầu tiên của sensor (startedAt). Route chung cho cả 3 role, không có prefix.

Params

Tham sốVị tríGiá trịMặc định
assignmentIdpathUUID—
sensorIdpathUUID — phải bound vào assignment—
intervalquery10s · 1m · 1h · 1D · 1W · 1M1h

Response data

{
  "assignmentId": "5a8d3f02-...",
  "sensorId": "4ec6f20b-...",
  "sensorType": "soil_moisture",
  "interval": "1h",
  "startedAt": "2026-05-14T00:00:00.000Z",  // reading đầu tiên; null nếu chưa có data
  "data": [                                  // sort ASC sẵn — vẽ thẳng
    { "timestamp": "2026-05-21T05:00:00.000Z", "value": 41.2 },
    { "timestamp": "2026-05-21T06:00:00.000Z", "value": 43.8 }
  ]
}
  • Tối đa 300 điểm; dài hơn → 300 bucket mới nhất.
  • Chưa có reading → data: [], startedAt: null.
Endpoint cũ vẫn còn: GET sensor-reading/{role}/assignment/:id/sensor/:id/series (raw, from/to/limit≤50) chưa gỡ — app/FE đang dùng thì không vỡ. Khuyến nghị chuyển sang series-interval cho chart mượt hơn.

6. API 3 — Summary stats (4 badge)

GET /sensor-reading/assignment/:assignmentId/sensor/:sensorId/stats?period=today Bước 4

Mô tả

Số liệu cho 4 badge phía trên chart. Một lần gọi trả cả 4 — đổi period gọi lại 1 lần. Route chung cho cả 3 role.

Query params

Tham sốGiá trịMặc định
periodtoday · 7d · 10dtoday

today = từ 00:00 hôm nay; 7d/10d = từ 7/10 ngày trước tới hiện tại.

Response data

{
  "assignmentId": "5a8d3f02-...",
  "sensorId": "4ec6f20b-...",
  "period": "7d",
  "currentValue": 94,    // badge 1 — giá trị mới nhất
  "minValue": 1,         // badge 2 — thấp nhất trong period
  "maxValue": 100,       // badge 3 — cao nhất trong period
  "alertCount": 83       // badge 4 — số lần alert trong period
}
Không có data trong period → cả 4 trường trả 0 (không bao giờ null).

7. Lỗi chung

HTTPKhi nàoXử lý client
401Thiếu / sai / hết hạn tokenVề màn đăng nhập.
403Role không thuộc owner/manager/farmerẨn tính năng.
404Milestone/assignment không tồn tại hoặc không có quyền; sensorId không bound vào assignmentBáo "không tìm thấy", quay lại list.

8. Ví dụ wiring

// role: "owner" | "manager" | "farmer"
async function api(path, token) {
  const res = await fetch(`${BASE}${path}`, { headers: { Authorization: `Bearer ${token}` } });
  const json = await res.json();
  if (!res.ok) throw new Error(json?.message ?? `HTTP ${res.status}`);
  return json.data;                                  // bóc wrapper
}

// ── Bước 1–2 — lấy assignmentId (route khác nhau theo role) ──────────────
let milestoneId, assignmentId;
if (role === "farmer") {
  const ms = await api('/production-milestone/farmer/current-upcoming-milestones', token);
  milestoneId = ms.data[0].id;
  const asg = await api(`/production-milestone/farmer/milestones/${milestoneId}/assignments`, token);
  assignmentId = asg.data[0].assignmentId;
} else {
  const ms = await api(`/production-milestone/${role}/crop-season`, token);
  milestoneId = ms.data[0].id;
  const asg = await api(`/production-milestone-iot-device/${role}/milestone/${milestoneId}/assignments`, token);
  assignmentId = asg[0].assignmentId;
}

// ── Bước 3 — list sensor (prefix theo role) ──────────────────────────────
const sensorList = await api(`/sensor-reading/${role}/assignment/${assignmentId}/latest`, token);

// ── Bước 4 — chi tiết 1 sensor: chart + badges (route chung) ─────────────
async function loadSensorScreen(assignmentId, sensorId, token, { interval = "1h", period = "today" } = {}) {
  const [series, stats] = await Promise.all([
    api(`/sensor-reading/assignment/${assignmentId}/sensor/${sensorId}/series-interval?interval=${interval}`, token),
    api(`/sensor-reading/assignment/${assignmentId}/sensor/${sensorId}/stats?period=${period}`, token),
  ]);
  return { series, stats };
}
// Đổi interval → gọi lại series-interval ; đổi period → gọi lại stats
Trục Y chart: dùng minValue/maxValue của sensor từ API 1 để cố định trục; vẽ threshold.optimalMin/optimalMax thành 2 đường ngưỡng an toàn. Mobile: chart qua react-native-gifted-charts / victory-native; refetchInterval ~30s cho latest/series.
